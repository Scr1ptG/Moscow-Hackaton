Backend (пакет backend)¶

Backend-оркестратор «Предиктора изменений в графике транспорта».

Отдельный сервис (FastAPI), не импортирует ML-код: общается с ML-сервисом по HTTP.

  • backend.config — настройки из переменных окружения;

  • backend.schedule — расписание, остановки и маршруты для карты;

  • backend.ml_client — клиент ML-сервиса с circuit breaker;

  • backend.state — состояние ТС, прогнозов, алертов, метрик;

  • backend.alerts — жизненный цикл инцидентов;

  • backend.worker — фоновые циклы: пересылка телеметрии и прогнозы;

  • backend.api / backend.main — REST + WebSocket для дашборда.

Расписание для backend: остановки, маршруты (линии для карты), участок до цели.

Backend читает те же CSV, что и ML-сервис, но использует их только для отображения (карта, карточка инцидента) и для живой оценки качества. Факт прибытия (time_fact_begin), если он есть в файле, никогда не передаётся в ML — он нужен лишь для метрик на реплее уже прошедшего дня.

Асинхронный клиент ML-сервиса с circuit breaker.

Если ML-сервис N раз подряд не ответил, breaker «размыкается»: запросы не шлются cooldown секунд (backend работает на последнем известном состоянии), затем пробный запрос (half-open) — при успехе breaker замыкается.

Один активный инцидент на ТС: он обновляется, пока риск держится, и закрывается, когда прогноз N циклов подряд «зелёный» или цель уже в прошлом без свежего прогноза.

list[dict]

Фоновые циклы backend: приём телеметрии, пересылка в ML, прогнозы, алерты, метрики.

Надёжность:

  • ML недоступен -> телеметрия копится в ограниченном буфере и досылается позже, прогнозы помечаются устаревшими (показывается последнее известное состояние);

  • поток телеметрии оборвался -> ТС помечаются «нет связи», сервис продолжает работать.
