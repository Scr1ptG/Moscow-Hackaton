**4. Сведения о производительности и список дополнительных возможностей**

Производительность (CPU, 1 поток; замеры в reports/latency.json, reports/scale_bench.json):
- Инференс модели 0.023 мс на точку; точное объяснение (TreeSHAP) 0.12 мс; полный онлайн-прогноз точки (признаки из потока + модель + калибровка + объяснение) 1.1 мс.
- Цикл прогноза по всему парку дня (10 ТС) 21 мс; нагрузочный тест 500 ТС — 1.13 с на ядро, 4 шарда — 0.28 с (линейное масштабирование, ~2.3 мс на ТС).
- Приём NDTP: ~41 тыс. навигационных записей/с на ядро; сквозной прогон реального дня (16 772 пакета, ×450) без потерь, ML-ответ 22 мс (p50) на весь парк.
- Качество (честная валидация без утечек): MAE 68.1 с на невиданных маршрутах и 65.7 с «на будущем» против 88.4 / 83.8 с у бейзлайна cur_dev_s (−23…−21%); лидерборд — 1.00000.
- Надёжность: при обрыве связи на 10 мин MAE 69.4 с, на 60 мин 72.6 с (сервис не падает, работает по последнему состоянию); при недоступности ML — буфер телеметрии и circuit breaker.

Дополнительные возможности:
1. Map matching NDTP-треков на маршрут: детектор прибытий на остановки по GPS (медианная ошибка ~4 с относительно фактов АСДУ).
2. Объяснимость: точное разложение прогноза на вклады факторов (база + вклады = прогноз), текст причины для диспетчера, паттерны поведения ТС перед сбоем; проверено метриками (deletion test, монотонность без нарушений, калибровка вне выборки).
3. What-if анализ в дашборде: доп. опоздание, доп. отстой на конечной, выпуск резервного ТС.
3а. Рекомендации диспетчеру в каждом алерте (резервное ТС, объезд/светофоры, информирование пассажиров, удержание при опережении) — по причине и уровню риска.
3б. Проблемные участки на карте: где ТС сегодня систематически теряют время (по фактическим прибытиям из GPS, без заглядывания в будущее); цвет риска на маршрутах; сводка по парку.
4. Вероятность опоздания, 80%-интервал и ожидаемая ошибка каждого прогноза (калибровка по out-of-fold).
5. Оптимизация инференса: ONNX Runtime (CatBoost 0.017 мс, нейросеть 0.16 мс, int8-квантизация), устранение конкуренции потоков LightGBM/ORT (ускорение ×30).
6. Ансамбль LightGBM + CatBoost + PyTorch GRU по последовательности телеметрии (исследовательская модель, GPU); в прод выбрана компактная модель — не хуже по честной валидации, в 10 раз быстрее.
7. Дообучение на новых данных: разметка из сырых выгрузок АСДУ, режимы full/warm, гейт champion/challenger, реестр версий, откат, горячая перезагрузка модели.
8. Горизонтальное масштабирование инференса: шардирование ТС между репликами ML-сервиса.
9. Деградация без падения: circuit breaker, буферизация, «последнее известное состояние», пометка потери связи.
10. Реплей исторического дня в протоколе NDTP и живые метрики качества на дашборде.
11. Честная оценка: найдены и не использованы утечки в данных (факты validate в train/test, manual_fill, синтетические копии), тест анти-утечки «офлайн = онлайн».
